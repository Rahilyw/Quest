## Source checks dropped or changed, and why

- **Mock location on iOS.** Dropped. `hooks/useLocation.ts` reads `location.mocked`, which
  only Android reports, so there is nothing to observe on iOS. Android row A25 covers it.
- **Server-only checks on Android.** First finisher, win-back, the admin alt-text rule, removal
  revoking a sticker and XP, and a report reaching admin run once, on iOS (I38–I40, I43, I56).
  They test the server, not the phone.
- **Account deletion "XP disappears".** Kept as "post, XP and Rankings entry gone; sign-in
  fails". A deleted account has no XP screen left to look at.
- **Selfie in the celebration.** Not a row. Card E4 shows it in completion views, which I18
  covers; card C kept the celebration as it was.
- **Runbook Step 0a/0c SQL checks** (drain over 100 rows, failure path) stay in the runbook and
  in `supabase/verify`. They are SQL, not device checks. Only the phone side (pushes arriving,
  taps routing) is in the checklist.
- **Sentry test error.** The app has no way to raise a test error on purpose: `captureException`
  is only called from `ErrorBoundary`. I67 checks for a session from the build, and I63 checks
  that feedback arrives through Sentry. Both prove the DSN works, but neither is the "test error"
  the ultra plan §1 asks for. A small follow-up card (for example a hidden "Send test error" in
  Settings, production only) would close it.
- **OTA "received".** expo-updates has no in-app indicator, so I64 / A58 ask the owner to name
  the visible change the update carries.
- **"Photos from here" relative time and the queue dot as digits** are folded into I17 and I26
  rather than separate rows.
